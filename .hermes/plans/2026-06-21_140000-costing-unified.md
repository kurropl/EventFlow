# Plan: Motor de Costes Unificado + Ingrediente Único

## Contexto de la sesión de grill
- Solo eventos en **draft** se recalculan automáticamente cuando cambia un coste de ingrediente. Los **accepted** / **won** quedan congelados con el coste del momento de aceptación.
- `unit_cost` tiene `NUMERIC(8,4)` — 4 dígitos decimales. Suficiente para `0.0234 €/g` y `12.50 €/kg` sin perder precisión.
- Tabla nueva `ingredient_costs` (FK a `ingredients(id)` y `event_shopping_items(item_id)`) separada de los metadatos de escandallo.
- Migración de datos incluida en el deploy — 3 scripts SQL. Nombres huérfanos se marcan `unit_cost = 0` y se etiquetan como "pendiente de asignar".
- Tests: casos borde (coste 0 → error, cantidad 0 → coste 0, dos ingredientes con mismo nombre → gana el más reciente).

## Archivos a modificar/crear

### 1. `src/lib/costing.ts` — Motor único de coste
- `computeEventCost(selectedItems, catalog, ingredients, guests)` → devuelve `{ total, margin, pvp }`
- `computeLineCost(ingredientId, quantity, unit)` → coste individual
- `computeEventMaterialCost(id, eventId)` → desde escandallo
- `normalizeToUnitBase(value, unit)` → pasa a g/ml/ud siempre

### 2. `src/lib/__tests__/costing.test.ts` — Tests de regresión
- Identidad entre los 3 puntos
- Coste 0 → error
- Escalado por comensales
- Margen mínimo 20%

### 3. `/api/costing/[id]/route.ts` — Endpoint GET que devuelve el coste calculado
- Recibe `eventId` + opcional `guestsOverride`
- Devuelve `{ total, margin, pvp, costPerUnit, ... }`
- No hace falta llamarlo desde tres sitios distintos — es el mismo endpoint

### 4. Migración SQL
- `ALTER TABLE event_shopping_items ADD COLUMN ingredient_id UUID REFERENCES ingredients(id)`
- Crear tabla `ingredient_costs` con `(eventId, orderId, ingredientId, unitCost, quantity, total)`
- Copiar datos existentes con `INSERT INTO ... SELECT ...`

### 5. Frontend
- `OperationsManager.tsx` — botón "Regenerar" llama a `/api/costing/[id]`
- `BillingPanel.tsx` — tabla de facturación usa `computeEventCost()` mismo endpoint
- `BudgetEditor.tsx` — ya usa `computeEventCost()` no recalcula inline

## Deploy
- `git push` → build automático
- `./scripts/2025-06-20-costing-migrate.sql` → `psql -f` en VPS
- `docker restart eventflow` → nuevo coste disponible

## Verificación
```bash
curl -s http://localhost:3020/api/costing/2049750c... | jq '.'
# { total: "...", margin: "...", pvp: "...", ... }
```

## Riesgos
- La migración de nombres huérfanos puede fallar si hay items con nombre vacío
- Los eventos en `accepted` mantienen el coste anterior — no hay inconsistencia
- Los decimales `NUMERIC(8,4)` son suficientes para cualquier escandallo real
